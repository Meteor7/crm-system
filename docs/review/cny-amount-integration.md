## 金额口径

- S2–S6 阶段金额、销售表 Pipeline：取销售填写的 amount_cny，以 Decimal 加总，再由前端按 ¥M 展示。商机原币种为 CNY / USD / EUR 都不影响该人民币值的使用。
- 明细、停滞商机和丢单均使用同一人民币金额。沿用 DTO 的 amount / currency 字段，currency=CNY；阶段明细增加金额展示，方便逐条核对。
- S1 只计数量，不进入 Pipeline 金额；S7 按实际 PO 日期计数量。商机金额不充当 Booking 实际人民币订单金额；订单实际金额、差额与达成率自 2026-09-18 起按订单本身的人民币金额计算（见 approved-ui-backend-contract.md 第 4 点）。
- amount_cny 缺失、空串、0 或非法数值均为缺金额，不回退到原币 amount；若汇总范围内有一条缺金额，汇总显示数据不足，不把已知部分伪装成完整总额。可靠范围内没有商机时金额为 0。
- 旧 schema 没有新列时，不查询该列，金额返回 insufficient / amount_cny_unavailable，数量仍可用。

## 历史

沿用已核验的 fields 历史覆盖范围及逆向回放，读取 amount_cny 的历史行：
- 阶段和销售 Pipeline 用参考时点的人民币金额、当时的商机负责人。
- 停滞行金额用参考时点；丢单行金额用 marked_lost 时点，重开后的改价不覆盖过去丢单金额。
- Claude 迁移与首次补填会写 from_value 为空的历史行。因此早于补填的时点保持缺失，不拿今天填的金额回填过去，也不从最早历史行推断覆盖起点。
- 业务已定历史数据全部可信（2026-09-18，集成时调整）：补填前的时点，原币种为 CNY 的商机用当时回放出的 amount；其他币种仍为缺失，不换算。实现在 cockpit_metrics.py 的 cny_amount_at。
- fields 覆盖配置必须依据实际部署、迁移和写入路径核验；本次没有自动填写或扩大配置。字段历史范围无法证明时继续显示数据不足。

PO 年累计仍按当前 Booking 状态和当前商机负责人统计；与历史 Pipeline 的归属时点不同，这是已定规则。

## Claude 部署验收

1. 在副本运行人民币金额迁移演练及 migrate；核对 CNY 商机带入值和 amount_cny 历史行。外币商机按 list_missing 清单由销售补填。

3. 将其中一笔保留未填状态，相关总额显示数据不足；补齐后恢复。S1 金额不计入 Pipeline。
4. 核对销售、客户主档区域和市场筛选下的总额与明细一致。
5. 比较补填前后及改价前后周期，旧周期不拿当前值补齐；丢单后改价不改变丢单时金额。
6. 同时回归实际 PO 日期的跨年、补录、更正、取消和回退，确认两个增量均上线。
