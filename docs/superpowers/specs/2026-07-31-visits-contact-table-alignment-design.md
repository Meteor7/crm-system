# 拜访页面联系人式表格对齐设计

## 目标

将“拜访管理”页面从顶部状态统计加双列卡片，统一为与“联系人主档”一致的数据展示结构：页面标题、筛选栏、单个白色表格容器、每条拜访占一行。

## 页面结构

1. 保留当前 `PageHeader`、新建拜访按钮和全部筛选条件。
2. 删除顶部四个拜访状态统计栏，不在页面其他位置重新制作统计卡片。
3. 使用与联系人页一致的 `crm-table` 表格展示所有拜访。
4. 每条拜访只占一个 `<tr>`，不使用卡片、折叠行或抽屉。

## 表格字段

从左到右展示：

1. 拜访主题：主题为主信息，编号为辅助信息。
2. 客户：客户名称。
3. 日期 / 方式：日期为主信息，On-site、Video 或 Phone 为辅助信息。
4. 负责人。
5. 拜访目标。
6. 拜访结果：未填写显示 `—`。
7. 下一步行动：行动内容为主信息，行动负责人和到期日为辅助信息；未填写显示 `—`。
8. 状态：复用当前 `StatusBadge`。
9. 操作：复用当前角色权限和状态流转按钮。

## 行为与权限

- 新建、编辑、完成拜访、提交纪要、经理审核、完成行动的接口和条件保持不变。
- `visit:create`、`visit:write`、`visit:review` 权限保持不变。
- 筛选、加载、空状态、错误提示和弹窗保持不变。
- 不改 `VisitDto`、Mock 数据、Frappe 边界或通知逻辑。

## 视觉规则

- 表格容器复用联系人页的白色背景、细边框、14px 圆角和横向滚动。
- 主信息使用较深文字，辅助信息使用较小的弱化文字。
- 操作按钮允许在同一个操作单元格内换行，但不改变按钮的优先级样式。
- 桌面端优先；不新增移动端专用设计。

## 验收标准

- 页面不存在 `.status-rail` 和 `.visit-card`。
- 页面存在一个 `.crm-table.visits-table`。
- 每条加载到的拜访对应一行。
- 每行能看到主题、客户、日期、方式、负责人、目标、结果、下一步、状态和当前角色可执行的操作。
- 原有拜访流程操作仍可打开对应弹窗或完成行动。
