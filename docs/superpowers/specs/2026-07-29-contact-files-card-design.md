# 联系人文件卡与顶部操作设计

## 背景

联系人详情页右侧当前包含“关联业务”和“数据质量”两张卡片。“数据质量”卡片同时承载“合并重复联系人”入口，但用户希望该位置对齐 Salesforce Contact 页面，改成联系人文件上传模块。

本次同时调整顶部操作区：

- “合并重复联系人”保留，但从右侧卡片移动到页面顶部。
- 仅优化顶部“删除联系人”按钮的 CSS；删除确认弹窗不改。

## 目标

1. 右下角展示 Salesforce 风格的联系人文件卡。
2. 联系人附件在当前本地 Mock 环境中可以上传、刷新后保留、下载和删除。
3. 联系人合并或硬删除时，附件与联系人生命周期保持一致。
4. 顶部操作符合现有 CRM 的深蓝、暖白、青绿色视觉体系，并对删除操作使用克制的危险色。

## 非目标

- 不改动联系人删除确认弹窗及通用 `ModalShell`。
- 不改动联系人列表页、Document Center 或其他业务模块的视觉。
- 不引入云对象存储、病毒扫描、版本控制、在线预览或共享链接。
- 不把本地 Mock 文件能力描述为已经接通的正式 Frappe 后端能力。
- 不进行 Git 提交、推送或分支操作。

## 页面与交互设计

### 顶部操作区

- “合并重复联系人”作为次级按钮显示在联系人详情页顶部，沿用现有次级操作的白底、描边和青绿色文字。
- 按钮仅在联系人为 Active 且当前角色具有 `contact:merge` 权限时显示。
- 点击后继续打开现有 `ContactMergeModal`，不改变合并表单和冲突校验。
- “删除联系人”继续作为独立顶部按钮显示，仅在具有 `contact:delete` 权限时显示。
- 删除按钮改为浅色背景、危险色描边和文字，保留 `Trash2` 图标；悬停时增加轻微危险色背景和边框反馈，键盘聚焦时显示清晰焦点环。
- 删除按钮不使用大面积实心红色，避免压过“编辑联系人”等主要操作。

### 文件卡

右侧第二张卡片从“数据质量”替换为“文件”，英文眉题使用 `FILES`，标题中显示当前文件数量。

空状态：

- 显示虚线边框上传区。
- 显示上传图标、“上传文件”按钮和“或拖放文件到此处”提示。
- 上传按钮和拖放区域触发同一个隐藏文件输入框。

有文件时：

- 上传区仍保留在文件列表上方，便于继续添加。
- 每个文件显示文件类型图标、文件名、可读文件大小和上传时间。
- 每行提供“下载”和“删除”图标按钮，并包含可访问性标签。
- 删除附件直接针对文件执行，不复用联系人硬删除弹窗。

文件约束：

- 支持 PDF、Word、Excel、PowerPoint、TXT、CSV、PNG、JPG/JPEG。
- 单文件最大 20 MB。
- 支持一次选择或拖入多个文件。
- 同名文件作为独立附件保存，不自动覆盖。

### 响应式布局

- 保持现有三列详情布局。
- 中等屏幕下，“关联业务”和“文件”继续并排。
- 小屏幕下两张卡片改为单列，上传区和文件操作保持可点击。

## 数据模型与存储

新增联系人附件模型：

- `id`
- `contactId`
- `fileName`
- `mimeType`
- `size`
- `uploadedAt`
- `uploadedBy`
- `blob`

文件 Blob 与元数据保存在独立的 IndexedDB 联系人文件仓库中。它不写入当前使用 localStorage 的 Sales Snapshot，避免 Blob 序列化失败或明显放大联系人主数据缓存。

仓库按 `contactId` 查询文件，并提供：

- 列出联系人文件
- 上传一个或多个文件
- 读取文件 Blob
- 删除单个文件
- 将重复联系人的文件迁移到保留主档
- 删除联系人时清理其全部文件

## API 边界

在 `CrmApi` 增加联系人文件的列表、上传、读取和删除方法。Mock Adapter 使用 IndexedDB 仓库实现。

Frappe Adapter 对这些方法明确返回 `NOT_IMPLEMENTED`，避免前端把本地 Mock 行为误认为正式后端已经具备文件权限、审计和存储能力。

联系人合并成功时，把重复联系人的附件 `contactId` 更新为保留主档 ID。联系人硬删除成功时，清理该联系人的全部附件。

## 状态与错误处理

- 文件卡独立处理加载、上传、下载和删除状态，不阻塞联系人主资料渲染。
- 上传期间禁用重复提交，并显示处理中状态。
- 文件类型不支持或超过 20 MB 时，在文件卡内显示明确错误，不调用存储层。
- IndexedDB 不可用、配额不足或读写失败时，在文件卡内显示可重试错误。
- 单个文件失败不清空已成功上传的其他文件。
- 下载使用临时 Object URL，触发后及时释放。

## 权限

- 查看联系人文件跟随 `contact:view`。
- 上传和删除联系人文件跟随 `contact:write`。
- 下载需要能查看该联系人。
- 合并和硬删除继续使用现有的 `contact:merge` 与 `contact:delete`。

2. 验证 TypeScript 类型检查与生产构建。
3. 在本地浏览器验证：
   - 顶部出现“合并重复联系人”。
   - 顶部删除按钮符合系统视觉且悬停、聚焦状态清晰。
   - 右下角不再显示“数据质量”卡片。
   - 文件可以点击上传和拖放上传。
   - 刷新后附件仍存在。
   - 文件可以下载并保持原内容。
   - 文件可以删除。
   - 合并联系人后附件出现在保留主档。
   - 硬删除联系人后附件被清理。
4. 确认删除确认弹窗和其他模块未发生视觉变化。
