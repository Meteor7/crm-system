# 可扩展客户业务领域设计

## 目标

客户档案的“业务领域”不再限定为 `Frontend` 和 `Advanced Packaging`。Sales 可以在下拉框底部选择“自定义领域”，填写新领域；保存客户后，该领域成为系统级选项，并同步用于所有客户业务领域的录入和筛选。

## 范围

- 客户新增表单支持选择已有领域或填写自定义领域。
- 客户编辑表单支持相同行为。
- Lead 转客户表单使用同一组领域选项。
- 客户列表的业务领域筛选使用同一组领域选项。
- Mock API 与 Frappe API 保持一致行为。
- 现有领域和现有客户数据保持不变。

本次不增加独立的领域管理页面，不提供重命名、合并或删除领域的能力。

## 数据来源与同步

后端提供统一的业务领域列表接口。Frappe 端以 Customer 的 `custom_crm_segment` 字段选项作为系统级来源，初始包含现有两个领域；Mock 端维护同等的可变领域集合。

创建或更新客户时，后端对领域名称做首尾空格清理并校验非空。若名称尚不存在，则先加入系统级领域选项，再保存客户。重复名称不会产生重复选项。接口返回的领域列表随后可被所有录入表单和客户筛选复用，从而满足全局同步要求。

领域值在 TypeScript 契约中由固定联合类型改为普通字符串，避免新领域被编译期限制。

## 前端交互

新增一个小型、可复用的业务领域选择组件：

- 演示员工152状态显示后端返回的全部领域。
- 下拉最后一项固定为“＋自定义领域”。
- 选择该项后显示文本输入框，用户输入的值直接成为表单字段值。
- 切换回已有领域时隐藏自定义输入框。
- 自定义值为空时不能提交，并显示明确错误。

客户新增、客户编辑和 Lead 转客户复用该组件。客户列表筛选不提供新增入口，但使用同一接口返回的领域列表，因此新领域在保存并刷新列表后立即可用于匹配筛选。

## 后端行为与权限

- 读取领域列表需要 `account:view` 权限。
- 新领域只通过客户创建或更新产生，因此沿用 `account:write` 权限；Sales 无法绕过既有客户范围和负责人校验。
- 领域名称按清理后的精确文本去重；本次不进行大小写或中英文同义词合并，以免错误合并合法分类。
- 若领域选项登记或客户保存失败，请求整体失败，不留下只登记领域但未保存客户的半成品状态。

## 错误处理

- 空白自定义领域：前端阻止提交，后端同时拒绝。
- 重复领域：复用已有选项，不报错。
- 列表读取失败：页面保留现有默认领域作为安全回退，并显示现有请求错误机制提供的信息；客户保存仍以服务端校验为准。
- 并发新增同名领域：后端在写入前重新读取并去重，最终只保留一个选项。

## 测试与验收

- 前端组件测试：已有选项、自定义入口、自定义输入、切换行为和空值校验。
- 页面测试：客户新增、编辑与 Lead 转客户都能提交自定义领域；客户筛选能看到新增领域。
- API 契约测试：领域列表请求映射正确。
- Mock API 测试：新增领域后全局列表包含该值且不重复。
- Frappe 服务测试：新增自定义领域可保存、字段选项同步、重复新增幂等、空白值拒绝。
- 运行相关 Vitest、后端账户测试及前端构建，确认无类型和集成回归。

## 成功标准

Sales 能在客户业务领域下拉底部添加一个非空自定义领域；客户保存成功后，该领域在其他客户的新增、编辑、Lead 转客户以及客户列表筛选中可见并可匹配，且系统中不会生成重复领域选项。
