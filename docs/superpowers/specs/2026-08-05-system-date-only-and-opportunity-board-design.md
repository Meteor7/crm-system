# 全系统日期展示与 Opportunity 八列看板设计

## 目标

1. 所有面向用户展示的时间统一为 `YYYY-MM-DD`，不显示小时、分钟或秒。
2. Opportunities 看板的八个阶段始终保持在同一横向行中，`Lost` 固定在最右侧，不换到下一行。

## 日期展示边界

- 仅改变前端可见文本，不截断 API DTO、数据库字段或前端状态中的原始时间。
- 后端继续保留完整时间，用于排序、审计、并发控制和记录唯一键。
- 日期输入字段继续使用 `input[type="date"]`；不新增时间输入，也不改变提交格式。
- `modified`、内部排序值、下载审计原始数据和事件键保持原值。
- 所有列表、详情、通知、评论、审批、历史、文件、Demo、Opportunity、Lead、Account、Contact 等页面中的可见时间均使用统一格式化函数。

## 统一格式化规则

新增 `formatDisplayDate(value, now?)`，返回 `YYYY-MM-DD` 或空占位符：

1. ISO 日期时间、带时区时间和 JavaScript 可解析时间按 `Asia/Shanghai` 转换后显示日期。
2. 已是 `YYYY-MM-DD` 的值原样返回。
3. `YYYY-MM-DD HH:mm[:ss]` 取同一日期部分。
4. `今天`、`今天 HH:mm`、`刚刚`、`当前待办`映射为上海时区当天日期。
5. `昨天`、`昨天 HH:mm`映射为上海时区前一天日期。
6. `M月D日` 使用上海时区当前年份补全。
7. `M-D` / `MM-DD` 使用上海时区当前年份补全。
8. `N 天前` 映射为上海时区当天向前 N 个自然日。
9. 无法识别的非空值保持原文，避免伪造日期；空值显示 `—`。

该函数只用于显示，不用于排序、持久化或业务判断。

## 覆盖策略

- 替换模板中直接展示的 `createdAt`、`updatedAt`、`uploadedAt`、`submittedAt`、历史 `at` 和其他时间戳。
- 替换已有局部时间格式化函数，例如联系人文件的上传时间和 Demo 评论时间。
- 已经是日期字段的 PO、Shipment、FAT、Booking、DDL、Visit、Action Due 等仍经过统一函数，以保证格式一致。
- 日历中的单独“日号”属于月视图结构，不转换成完整日期，以免破坏日历布局；日历事件详情仍显示完整 `YYYY-MM-DD`。
- 文案中的业务时长或相对期限（例如“未来 7 天”“24×7”）不是时间戳，不修改。

## Opportunity 看板

- 阶段顺序继续使用现有八个阶段：`需求发现`、`技术确认`、`Demo验证`、`预算审批`、`报价`、`采购流程`、`Won`、`Lost`。
- 看板网格由七列修正为八列。
- 设置满足八列最小卡片宽度的 `min-width`，桌面和窄屏通过外层容器横向滚动。
- 不改变阶段数据、拖拽行为、过滤器、卡片内容或后端接口。

## 测试与验收

1. 日期工具覆盖 ISO、带时区、日期、日期时间、今天、昨天、刚刚、当前待办、月日、空值和不可识别文本。
2. 代表性通知、评论、文件、历史和客户更新时间只显示 `YYYY-MM-DD`，不含 `HH:mm`。
3. 源码审计不再发现直接展示完整时间戳的已知模板路径。
4. Opportunity 看板渲染八列，顺序正确，`Lost` 为最后一列，CSS 网格为八列且不换行。
5. 聚焦测试、TypeScript 检查与 Frappe 生产构建通过。
6. 重新生成受控 `backend/build/rayher_crm.zip`，确保 Docker 使用新静态资源。
7. 本地 Docker frontend、backend 与 db 健康，`/crm` 返回 HTTP 200；不删除 volumes。

## 非目标

- 不修改数据库时间字段类型。
- 不迁移历史记录或删除时间精度。
- 不改变后端响应契约。
- 不修改时区配置或业务日期计算规则。
- 不顺带修复现有完整测试集中的范围外失败。
