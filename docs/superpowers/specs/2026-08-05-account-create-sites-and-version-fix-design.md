# 客户新增厂区与版本校验修复设计

日期：2026-08-05

## 目标

同时解决两个客户档案问题：

1. 在客户详情中保存新增厂区时，客户更新请求必须携带当前记录的 `modified` 版本，避免后端返回 `expectedModified is required`。
2. 在“新增客户”弹窗中复用详情页的厂区编辑能力，允许用户在一次建档操作中录入零个或多个厂区。

## 交互设计

“新增客户”保留现有客户主数据字段，并在负责人字段下增加“厂区信息”区域。用户可点击“增加厂区”添加任意数量的厂区，也可删除尚未提交的厂区。厂区不是客户建档的必填条件；但一旦添加某个厂区，该厂区的名称、城市、类型、制程/用途和状态都必须填写。

新增客户与修改客户使用相同字段、状态选项和视觉结构，避免两处录入规则不一致。新厂区的城市默认取当前客户城市，之后允许独立修改。

## 数据流

新增客户提交时：

1. 调用 `createAccount(accountForm)` 创建客户。
2. 使用返回的客户 ID，按用户录入顺序调用 `createAccountSite(accountId, siteInput)` 创建厂区。
3. 全部成功后关闭弹窗、刷新客户列表，并跳转到新客户详情页。

客户详情保存时，调用 `updateAccount(accountId, accountForm, account.modified)`，通过后再执行厂区新增、修改或删除。

本次不新增后端批量接口，不改变现有 Account 与 Site 数据结构。

## 错误处理

如果客户本身创建失败，弹窗保持打开并显示现有错误信息，不写入厂区。

如果客户创建成功但某个厂区创建失败，弹窗保持打开并明确提示“客户已创建，但厂区保存失败”，避免用户误以为客户也未创建。再次点击提交不得重复创建客户；页面应保留已创建客户 ID，并只重试未完成的厂区。用户关闭弹窗后可从客户详情继续维护厂区。

## 测试与验收

- 客户详情更新请求包含当前 `modified`，原错误不再出现。
- 新增客户不添加厂区时，现有建档流程保持不变。
- 新增客户添加一个或多个厂区时，先创建客户，再用返回 ID 创建全部厂区。
- 新增厂区默认城市来自客户城市，厂区字段校验与详情页一致。
- 厂区创建中途失败时不重复创建客户，并可重试剩余厂区。
- 相关前端测试、类型检查和 Frappe 模式构建通过后再更新本地 Docker 服务。

## 非目标

- 不引入新的后端事务或批量创建 API。
- 不要求客户必须至少有一个厂区。
- 不修改联系人、Lead 转换或其他模块的建档流程。
