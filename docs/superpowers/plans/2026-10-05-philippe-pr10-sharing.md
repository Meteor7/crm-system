# PR10 查询共享与一致导出

基于 PR09。保存查询增加接收人子表，所有者可以共享、撤销、更新和删除；接收者只能读取定义、按自己的权限运行，或另存一份独立的个人查询。共享不授予客户、商机、来源活动或附件访问权，不发送站外通知。接收者看不到其他接收人的名单。原生文档 API 仍禁止直接读写查询及其子表，服务接口实施所有者和接收者检查。

接收人必须是启用且只有一个 CRM 角色的其他用户；按 User 的真实 ID 去重，最多 100 人。共享、撤销及编辑使用 expectedModified 乐观锁，修改留下原生 Version。另存的新查询初始不共享；原查询撤销不删除已另存的独立定义。

原生用户合并后，接收人仍按有效访问集合解释：相同身份仅展示一次，查询作者不列为自己的接收人。读取不改写原生 Link 或审计；所有者下一次通过已有版本化分享接口保存时，将规范化的集合写回子表。重复接收人不携带不同业务值，因此不沿用目标／承诺的合并拒绝规则，也不增加用户合并期间的写锁。

从保存查询运行列表或导出时传入 savedQuery `{id, modified}`，服务在当前事务中锁定查询和接收人，校验实时访问与版本；撤销、删除或旧版本都会拒绝。传入条件仍可临时修改并另存，权限不会随条件放宽。界面独立保存实际加载的版本，后台刷新列表不擅自替换当前版本；主动刷新明确重新加载最新定义并丢弃本地改动。

POST export_opportunities 一次返回按同一个查询计算的完整有序记录、汇总、分组与 asOf，不分页拼接。Frappe/MariaDB 的请求事务提供一致读取，每次请求重新检查当前用户权限。前端在身份切换或退出后丢弃响应，并核对返回行数和唯一 ID。导出等待服务端响应的默认超时为 120 秒，与部署中的 Gunicorn／代理预算一致，普通接口仍为 30 秒；调用方显式 timeoutMs 仍生效，也可单独设置 exportTimeoutMs。超时不返回部分导出。

普通 JSON 和导出的总超时覆盖响应头及正文读取的完整过程。二进制附件允许持续传输的大文件超过 30 秒：响应头等待仍有时限，收到响应头后以及每次收到非空正文块后重新开始空闲计时，连续 30 秒无数据才中止；显式 timeoutMs 同样适用于此空闲时限。正文中断或超过期限返回可重试的网络错误，成功或失败结束后均清理计时器。

Excel 包含 Summary 页和按当前分组拆分的明细页，只导出所选列。汇总记录查询名称、条件、时间、总数、已知人民币百万元与金额缺失数；过长条件拆成编号单元格，完整保留。人民币百万元先按十进制字符串精确换算，15 位有效数字内写可求和的数值，超出 Excel 数字精度时写精确文本，明细与汇总使用同一规则并在说明中标明；汇总允许超过单条 DECIMAL(20,2) 上限。业务日期按上海日历写成 Excel 日期；未知日期及证据不完整的最后活动日期留空。名称清除文件与工作表非法字符，文件名按 Unicode 字符截断，工作表截断和去重不切断代理对；所有业务文本以 inlineStr 写入，不能成为公式。

验证覆盖共享与撤销、非所有者拒绝、另存隔离、失效版本、接收人校验、单次完整导出、实时范围变化及真实两连接的撤销竞态；前端覆盖只读入口、撤销、刷新版本、元数据、分组名称冲突、类型化金额日期及公式文本。新增 6 项原生 Frappe 用例仍待完整门禁执行；双审与最终门禁结果另行登记。

首轮双审修复：已授权保存定义中的销售范围和嵌套 in／not_in 谓词允许继续使用，实际数据始终先按接收者权限读取。另存、更新时也传 savedQuery 来源及版本，只接纳该来源已有的额外销售值；任意新值仍拒绝，撤销后不能再据此另存。列表／导出使用共享当前读锁，两名读者可同时读取；变更操作从一开始取得排他锁，避免升级死锁。版本比较直接使用同一当前读结果。共享与查询编辑显式保留 Frappe Version，新增内容断言；两连接测试先释放 setup 的所有者范围锁，再验证并发共享锁和旧快照下撤销。现有业务文本可超出 Excel 单元格限制时按完整 Unicode 字符分段保留。

定义修改互斥：保存、共享和删除先通过 tabSeries 保留键 rayher_crm.saved_query_write_lock 取得事务排他锁；该键不生成业务编号。低频定义修改串行，避免 A、B 同时复制对方查询时持有彼此来源锁的循环等待。列表和导出不取此修改锁，仍可并发读取。双连接测试保持第一修改事务未提交，验证第二请求等待修改锁，释放后两份独立副本均成功提交。

并发复审修复：共享保留最前面的定义修改互斥锁，然后按数据库 name 顺序一次锁定全部接收者 User，再校验角色，最后锁查询和接收人子行。该顺序与 Frappe 原生用户改名／合并的 User→Link 顺序一致；大小写别名不会按客户端字符串的顺序反向锁用户。互斥键所在 tabSeries 没有 owner／modified_by，避开原生 User.after_rename 对普通表审计字段的扫描锁；单条 upsert 获取排他锁，提交或回滚时自动释放。真实双连接回归在旧实现复现改名／合并时的死锁，以及大小写别名造成的用户锁反转；新实现等待身份变化完成后拒绝过时的旧用户，再用当前用户重试。
