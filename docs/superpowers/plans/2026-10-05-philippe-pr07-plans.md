# PR07 计划报价、跟进和展会活动

基于 PR03 活动事实与已通过本地双审的 PR05 行动状态候选 0f833f9a。最终候选随依赖审查修复同步，并单独完成本项双审与门禁。

报价计划日期直接保存在原报价主档，只能为当前草稿设置，可清空取消。发布后自动退出待发计划；修订草稿可重新安排。计划金额读取当前草稿的人民币总额，外币不换算，不把未知金额当零。实际首次发出报价仍使用 PR03 的发布快照规则。

报价跟进作为原报价的子记录维护：到期日、内容、Open／Done／Cancelled 状态和备注。沿用原报价的访问范围，包括尚未关联商机的报价；商机行动要求已有商机，因此不能承载全部报价跟进。原报价和商机行动继续是各自唯一业务来源，不再复制成另一套活动表。完成时记录服务端时间、当时销售及开放的已发布版本；后续报价关闭不抹掉已完成事实。重开或取消清除当前完成快照，完成后的备注修改保留时间。保存以报价版本作并发检查，修改进入版本历史。未完成且到期在上期的跟进自动结转。

新增独立 CRM Event 用于无现有来源的展会等活动，提供销售归属、起止日期、可选客户／商机关联、完成及取消；未关联客户的活动可以记录自己的地域／市场／设备，缺失分类保留未知。销售管理自己的活动，经理可管理全部，工程师不开放。跨期活动按与计划周期相交展示，每个周期中一条；完成只按实际完成时间计一次，不按持续天数计活动数。

Demo 保留已就绪且进行中的清单，但只有明确计划日期落入当前周期才计“本期安排”。无日期和周期外的进行中 Demo 单独标注，不能冒充本期安排数。新增来源接入统一活动投影，Review 可读取事实；跟进 KPI 卡与目标由 PR04 接入。

往期未完成报价及跟进进入独立 `quotation_carryover` 明细，页面显示数量和入口，保持原日期与来源，不纳入本期安排数。原商机行动逾期仍由 Warnings 查看。新增活动、报价、跟进纳入销售及市场计划汇总。

所有新增入口复用当前业务范围与角色，计划和完成不触发外部邮件或日历邀请。本项不包含历史完成业务补录、设备完整排程或独立预测账。

Event 列表、数量、详情与保存同时遵守 Frappe 原生 User Permission；关联修改检查拟保存的客户、商机和负责人。创建或更换归属只能选当前有效销售，经理仍可保持原归属取消停用销售的旧活动、维护已完成记录的备注，完成快照不因此改写。报价发布、弃草稿和新建修订清除旧计划发送日期，修订需要显式重新安排。

原生门禁后的兼容检查：Event 和报价计划保存显式开启 Version，保证 Frappe 测试上下文也生成审计。原有 schema loader 单测隔离新增 Event 读取，避免假的元数据进入真实权限查询。旧 Demo 工作流测试同时检查本期安排与其他进行中 Demo，两组不重叠且分别与计数一致；需要计入本期安排的组合样例明确设置 Demo 截止日。完整计划汇总合同包含报价、跟进和活动七类。

Event 保存先锁定拟保存的 User，再锁 Event 及关联业务记录，与原生用户改名／合并的顺序一致；只有新增或重新指派才要求当前有效销售，经理维护停用销售的既有历史仍可用。原生双连接测试覆盖“原创建者已不是当前负责人，再指派回原创建者”与真实用户改名／合并重叠的情况，检查旧身份拒绝、创建者元数据更新及随后重新指派的审计。

Review／Plan 的 Event 读取在数据库中按客户范围筛选，同时保留无客户的独立活动及原生行权限；统计投影不传输备注和修改时间。跟进完成时间显示为上海日期及分钟，可区分同日多次完成。管理员身份合并后，停用或非销售账号的既有 Event 仍可由经理在原归属下取消或维护历史；新建及重新指派继续要求有效销售，不因身份归并放宽读取权限。
