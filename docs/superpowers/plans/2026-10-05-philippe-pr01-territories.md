# PR01 地域维护与销售归属

基线：`bce349872e063e29b6717f7c1a4483d1d58f582f`；分支：`codex/philippe-01-territories`。本项独立于 PR03 的活动统计改动。

## 交付合同

- 经理从“地域与归属”页维护分组和末级区域，支持新增、调整上级、排序、启停；名字与节点类型保存后固定。树最多四层，区域不能下设地域，不允许环；移动分组时同时检查后代深度。无效旧分支可以逐支修复。
- 停用指停止新的销售归属；先停用或移走启用的子节点。已有业务记录和地域筛选保留，客户区域值不改写。停用后允许结束、撤销已有归属，不允许扩展其有效期间。启停不改变数据访问权限。
- 销售归属只登记在末级区域。一名销售可负责多个区域；同一区域的非撤销记录不能有重叠日期，起止日期均含当天，空截止日表示持续有效。换负责人应结束或撤销旧记录，再建立新记录；旧记录的负责人和区域不可改写。
- 经理可以修改日期或撤销错误记录，Frappe Version 保留更改历史；所有编辑带版本校验。统一的地域目录锁覆盖层级和归属写入，避免同一区域的并发首条归属绕过重叠检查。
- 保留现有区域英文规范和别名规则，自定义区域通过原名挂接；未挂接名称在页面单列，没有自动猜测客户或销售归属。客户尚未使用的显式维护区域也不会在后续迁移中被清除。
- 新归属 DocType 为 service_only，只有经理服务入口可读取或修改；原有客户/商机权限规则保持适用。

## 区域迁移后的查询边界

地域归属写入按 User／Has Role → 地域目录 → 归属记录的顺序锁定，资格采用数据库当前读取。业务接口在 CAS 前、原生 controller 在 insert／_save 的框架行锁前取得身份锁和目录锁；原生地域节点保存也先取得目录锁，再进入框架行锁。新增、恢复和扩大期间拒绝已失效人员，缩短、备注及取消仍保留历史维护能力。原生 User 改名和合并在遍历 Link 前按数据库顺序锁定双方，防止旧事务在身份变化提交后写回旧归属。两连接原生回归覆盖停用、角色移除、改名、合并、直接原生保存和历史维护，以及原生保存与业务 API 同时修改不同记录的目录锁顺序。

原生新建分组与经理 API 执行同样的注册区域名称保护；既有历史分组仍可维护。普通 Frappe insert／save 本身会在 controller.validate 之前将 territory、parent_territory、sales_owner Link 改为数据库中的存储拼写，事实回归覆盖原生插入和再次保存，不重复实现框架归一化。

原生新建地域节点同样要求不超过 100 字符的英文名称。新末级节点在目录锁内匹配并登记 Customer 区域；若提交的是已有选项的不同拼写，明确拒绝并要求使用登记名称，避免字段命名已经完成后只修改标题而留下不同的文档 ID。已有中文、别名节点继续允许维护。历史无效创建场景在迁移测试中用明确的旧数据夹具保留，新原生插入另有真实接口校验覆盖。

当区域选项同时保存规范拼写和旧末级节点的精确拼写时，迁移保留原节点、父级、销售归属和保存查询，不自动统一客户数据。仅规范拼写已登记的旧修复仍执行；未被原节点覆盖的另一选项继续显示为未映射，供经理明确处理。原生回归包含预设及自定义区域，比较迁移前后父级范围、scope／in／not_in 的真实商机结果，并重复执行迁移。

保存查询通过 Python 精确匹配地域路径。迁移旧分组时，仅当旧组名精确属于已注册区域选项才保留该旧值；即使另一个大小写选项先发现数据库碰撞，也不能丢失原先命中的客户。若仅注册了不同大小写的名称，则不额外追加它，避免扩大原查询集合。原生回归直接比较迁移前后 scope／in／not_in 的实际商机结果，并验证重复执行。

保存查询的地域引用也随大小写末级节点重命名更新。原最多 100 个地域值可能因同名分组拆分而增至 200；仅地域列表上限扩为 200，其他列表仍为 100，条件数量不变；保存定义上限为 256 KiB，容纳旧 64 KiB 定义的无损扩展。原生回归启用真实区域就绪配置，覆盖 100 值的 scope、in、not_in 迁移后再次校验及另存，并验证末级节点重命名后的保存定义。

第三轮远端复审确认：旧站点在 post-model-sync 初始化之前，由模型同步为所有旧行填充新增字段默认值。因此 `is_group` 默认设为 0，初始化仅提升实际父节点，并保留后来明确维护的空组；服务创建和默认树种子均显式指定节点类型。新增原生测试读取实际安装列的 SQL DEFAULT 来复现升级填充值，覆盖旧大小写父级 Link、末级重命名、客户原值、明确空组和二次执行后的销售归属。此前 90d64468 完整门禁通过 1427 UI／899 native；此修复新增的升级回归和最终完整门禁仍待执行。
