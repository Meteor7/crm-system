# PR08 个人承诺与设备汇总

基于 PR04 集成版本，复用 PR02 目标规则和 PR07 计划来源。Plan 继续是经理周会页面，由经理记录各销售对选定周／月／季／年的活动承诺。承诺是独立的数量意向，不改变源业务记录；已安排数量继续从拜访、Demo、待发报价、跟进、行动及 Event 实时汇总。预计订单金额仍只取商机预计 PO 日期、人民币金额和原概率档位，不新增金额承诺或独立预测账。

## 个人承诺和目标

承诺按销售、指标、期间及期间首日唯一保存，支持明确的零，不把未填写当零。首次创建及更新串行检查当前记录，更新校验 modified。仅经理可保存，销售必须当前启用且只有 CRM Sales 角色；历史记录保留但不允许给失效人员新录承诺。原生 DocType 只允许经理读取，写入通过业务服务，变更使用 Version 留痕。页面提供最近 20 次修订，注明截断上限。

编辑期间销售被改名、合并、停用或更改角色时，服务返回版本冲突，页面保留草稿并要求重新加载计划；数量或备注校验失败仍允许原地修正。原生用户合并若将造成同一业务键的承诺冲突，在改写 Link 前拒绝，要求管理员先核对处理；不自动选择、相加或删除任一承诺。历史已经存在的重复承诺继续只读展示每条记录的编号、数量、备注、修改人及独立修订历史，核对前保持数据不足。审计读取以可见记录为范围，每批最多 500 个记录编号，通过 MariaDB 10.6 窗口函数分别取每条记录的最新 20 次修改，不再逐条查询，也不暴露筛选外记录。

支持客户沟通、合格线索、完成测试轮次、首次报价、报价跟进、行动和 Event 承诺。目标沿用对应个人指标及期间；周目标可使用已生效的周默认值，不乘算成月、季或年。行动和 Event 尚无独立目标，显示不适用。合格线索没有计划源记录，已安排显示不适用。Demo 安排数是项目数，承诺及目标是完成测试轮次；待发报价可含换版而承诺及目标只计首发。页面明确标出这些单位差异，不计算误导的完成比例。

团队承诺和目标逐成员汇总，任一缺项单列缺失并保持未设置／数据不足。单个销售有该项实际贡献但已不具备目标资格时仍参与该指标完整性判断。地域、市场或设备筛选没有对应的承诺分配，显示不适用并禁用编辑，不按比例猜分配。

读取历史承诺时按数据库 User 身份规范化负责人大小写，使个人筛选、团队汇总、重复记录和审计采用同一身份；读取不会改写历史 Link、修改时间或 Version。期间查询使用期间／首日索引，保存与合并检查使用负责人开头的业务键索引；索引均不强加唯一约束，历史冲突继续保留待核对。

## 设备分组及明细

沿用设备目录的规范化身份：来源关联商机的设备，独立 Event 使用自己选择的设备。每个来源仅进入一个组；缺设备单列未分类。为避免将已关闭商机上的活动误判为缺设备，未在开放商机列表中的关联商机也读取平台信息。

设备卡片只统计本期已安排活动和本期预计 PO，不把结转事项或其他进行中 Demo 混入本期数量。活动数、PO 数和金额均由同一组原始行计算。金额缺失单列，保留已知小计；未排日期的来源使对应组活动数显示数据不足。点击设备组使用服务器过滤后的同一集合分页，非法组 ID 拒绝，不退化成全部数据。

## 验证

承诺写入使用独立 Series 记录的原子 upsert 作为事务互斥，再锁销售身份及承诺记录。Series 没有用户审计字段，避免原生 User 改名／合并扫描 DocType 时与保存互相等待。新增真实双连接回归覆盖这两个并发场景，要求旧身份保存返回版本冲突、现有承诺及审计保留，并可用新身份重试。

合并检查先按数据库顺序锁住两个 User，再当前读取承诺冲突，不取得 Series 锁；即使事务已有旧的一致性快照，也能发现后来提交的冲突。非冲突合并保留记录编号、值、修改时间和审计；归并到已停用身份仍保留历史，当前录入资格保持原规则。

承诺保存遇到临时网络或服务端故障时保留数量和会议备注，允许直接重试；只有版本／人员状态冲突要求重新加载。保存期间如果计划本身已刷新，随后到达的网络错误不解除草稿失效状态，仍需加载当前记录后编辑。

已有 Plan 纯规则及新增设备分组回归共 26 项通过；首轮承诺表单、Plan 页和 Frappe API 共 69 项通过。新增原生测试覆盖经理权限、原生拒写、唯一身份／冲突／审计、零与未设置、期间目标、筛选不分配和设备明细先过滤再分页。原生测试与完整门禁待执行，双审与发布结果另记。
