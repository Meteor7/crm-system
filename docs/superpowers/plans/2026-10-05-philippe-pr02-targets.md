# PR02 团队和地域目标汇总

基于 PR01 地域维护候选。团队周目标按用户确认的“个人目标求和”实施，不增加独立团队数值。

个人目标原数据、键值和接口继续可读。团队目标逐人求和，基础成员为启用且 CRM 角色仅为 Sales 的人员，与目标编辑及保存规则一致；历史销售仍可用于筛选。所选期间名单外负责人只加入其实际参与的指标，明确显示“当前无法分配目标”，已有历史目标仍可使用，没有目标则标为不可完整比较，不把未知值补零。没有当期活动的停用人员不再持续影响团队目标。成员清单随当前 CRM 人员范围变化，不宣称还原历史组织名册。每个来源明确显示目标或缺失。某人未填时显示未设置或汇总不完整，不把剩余人的和显示成团队完整目标。默认周目标只用于对应周，从未来生效周一开始；月、季度、年只能使用分别填写的目标，不能乘周数。

年度订单目标在地域叶节点填写，父节点求后代叶节点之和，每个叶节点只计一次，不填写或叠加父级目标。停用节点仍属于分类历史；无法映射到叶节点的客户地域（包括误用分组名和空地域）列出缺口，全部范围不冒充完整。团队年度订单目标来自叶地域年度目标汇总；销售个人年度目标沿用现有值，两者不相加。选中销售并加地域筛选、或市场/设备筛选时，不分摊目标；地域筛选的活动周目标也不分摊个人总目标。

目标保存仅经理，检查有效销售或地域叶节点、非负值、整数活动数量和两位小数人民币金额。保留乐观版本检查与版本历史；新增字段不猜客户/销售归属，不迁移旧个人年度数值到地域。年度计划线按实际年份天数，覆盖倍数复用现有剩余年度目标，缺失/零/达标三种情况分别处理。

页面提供目标来源明细和地域年度编辑；图表及达成率使用当前范围的同一目标。该演示员工116与人员范围显示在页面，接受后续业务口径修订。

目标写入使用专属 Series 记录的原子 upsert，在整个事务中串行化首次新增及修改，再按目标范围锁定地域目录或当前销售身份，最后锁定业务记录。Series 必须先于地域目录，避免地域年度目标、个人目标和销售归属同时保存时形成目录 → Series → User → 目录的三方等待。互斥记录没有 owner／modified_by 字段，避免与 Frappe User 改名、合并后的审计字段扫描反向等待。原生双连接回归覆盖保存与真实改名／合并同时发生、旧身份拒绝、原记录和审计保留，以及重新加载身份后的编辑；三连接回归覆盖两种目标与 API／原生归属保存全部完成并保留正确值。

用户身份合并前，先按数据库顺序锁定两名用户，再以当前读取检查双方个人目标的 metric／period／anchor。相同业务键会明确拒绝合并，演示员工170须先协调冲突；不自动选一个目标值或删除审计。旧空 Sales scope 和大小写差异按数据库规则识别。此处不取得 Series 锁，避免与目标保存的锁顺序反转。存量重复记录继续按不完整显示并拒绝歧义编辑。

身份合并与新建／重新指派的资格检查不同。无目标碰撞时，历史目标可以随身份归并到停用用户；当前可分配目标名单仍排除该用户，历史数值保持可读。不新增全局 active Sales 合并限制。

Review、Warnings 和明细统计仅从数据库读取所选期间的活动目标、各销售各指标最新已生效的默认周目标，以及上海 asOf 年度订单目标。默认周目标同一生效日上的重复行全部保留，不选胜者；显式当周目标优先。补充期间及默认值读取索引，不把全部历史目标送入浏览器。

编辑器独立按 scope／销售或地域／metric／period／anchor 精确读取目标和 modified；未设置返回空值，重复记录返回冲突。读取允许历史身份和历史生效日，写入资格规则不变。加载及失败时禁止保存，失败可重试；切换期间、关闭、身份切换时丢弃旧响应。保存结果保留新的版本，即使刷新后的 Review 不包含该期间，仍可继续编辑。
