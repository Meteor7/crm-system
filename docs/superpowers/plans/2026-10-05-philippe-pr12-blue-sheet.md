# PR12 Blue Sheet 联动

基于 PR04 集成头 722c3e9a，包含活动事实、Warnings、Plan、目标及地域管理，以及 Plan 原生门禁修复。原有商机行动继续按到期日和完成状态进入 Plan；本 PR 不重复创建行动。

## 红旗与兼容

商机新增 `red_flag_records` JSON，每条保留稳定 ID、原文、严重程度（未分类／Low／Medium／High）、状态（Open／Resolved），以及服务端修改人和 UTC 时间。旧 `red_flags` 字符串数组继续返回并同步保存。历史迁移按商机、原顺序和文字生成稳定 ID，重复文字保留为不同记录，未知严重程度、编辑人和时间不补造。迁移幂等且不改商机 modified。

旧文字编辑器保存相同文字时，按出现次数匹配已有记录，保留 ID、状态及严重程度。删除文字相当于删除对应红旗；改变文字在旧编辑器中属于删除旧记录并新增未分类红旗。新结构编辑器可在保留 ID 的情况下修改文字、严重程度和状态。新文字上限 4,000 字，最多 200 条；超过该限制的旧列表和原文可保留或缩减。修改在商机锁和 expectedModified 校验下完成，并写入字段历史；客户端不能指定新记录 ID 或修改审计信息。

Warnings 和 Review 明细按每条未解决红旗显示一个当前提醒，采用当前客户地域／市场、当前商机销售／设备范围及原生商机读取权限，仅包含进行中的商机。红旗与所选历史周期无关，界面明确说明。修改原记录保留提醒身份，解决、删除或结束商机后清除。未分类严重程度单独显示。

## 概率建议

生产默认无档位映射。业务尚未提供正式规则及样例，因此未配置或无效配置显示“暂不推荐档位”。不存在 AI 推断，也不引入概率百分比。

站点配置 `crm_blue_sheet_probability_rules` 接收一个经过业务确认的有序规则集：

- `version`：1–100 字非空版本；`rules`：1–40 条规则，按顺序使用第一条匹配项。
- 每条规则必须提供唯一 `id`、已有四档之一的 `level`、明确的 `reason`。
- `requiredRoles` 指定必须覆盖的关键人角色；`supportingRoles` 指定必须存在 Support 关键人的角色。名称沿用现有带空格的角色值，如 `Economic Buyer`。
- `maxOpenRedFlags`、`maxHighRedFlags`、`maxOpposedStakeholders` 为非负整数上限；`requireClassifiedRedFlags` 明确是否要求未解决红旗均已分类。解决的红旗不计入这组事实。
- 整个规则集先校验，任一规则无效则整个建议不可用；没有匹配时保留当前档位。测试规则仅存在测试代码中，不安装到站点配置。

Manager／Sales 可检查事实、规则版本和匹配理由，Engineer 不可访问关键人衍生建议。销售负责人点击确认后，后端重新锁商机及当前关键人，比较商机版本和包含规则、红旗、关键人的指纹。规则改变即使复用版本名也会拒绝旧建议；关键人修改即使没有修改父记录时间也会拒绝。概率更新复用现有服务，降档仍必须填写原因和补救计划，并保留概率历史、补救计划、通知及本次建议依据。已结束商机冻结，Manager 无法代替负责人确认。

## 竞争信息与复盘

经理打开丢单复盘后，可主动读取当前 Blue Sheet 竞争信息，再把单条记录引用到草稿。引用含商机 ID、读取记录的 modified、竞争方、优势及应对，标明“非已确认丢单原因”。不自动选择分类、不自动提交复盘。经理正式提交后，引用文字与结论一起进入既有复盘修订历史。草稿长度不超过 4,000 字；页面按纯文本显示。

## API 与验证

新增 GET `opportunities.get_blue_sheet_assessment`；POST `opportunities.save_blue_sheet_flags` 和 `opportunities.apply_blue_sheet_suggestion`，写入携带 `id`、`input`、`expectedModified`。测试替身只有抛错类型桩，新行为使用 API stub／HTTP fake。

已编写 8 项纯规则测试、11 项 Frappe 原生测试，以及红旗编辑、冲突、显式确认、身份切换、竞争引用、Warnings 和 HTTP 演示员工116回归。最终头双审及完整门禁尚待执行；正式概率规则仍待业务提供并验收。

## 首轮对抗性审查修订

旧字符串 API 与结构编辑器统一执行条数及长度校验，同时保留超限历史记录例外。一般商机编辑对已有结构红旗不再提供逐行重建入口，改为提示在 Blue Sheet 维护；其保存请求省略红旗字段。服务端不再修剪红旗首尾空白，未显式编辑红旗时保留完整记录，因此多行文字、稳定 ID、已解决状态和严重程度不会被改标题或概率确认重建。

写入先当前锁定商机及客户并复核可见性，适用于专门红旗保存、旧商机更新和建议确认。建议指纹加入关键人 contact 与微秒 modified，角色、立场相同的联系人改绑也会拒绝旧建议。迁移安装 `(opportunity, archived, name)` 索引，并在关键人查询中明确使用它，防止当前锁定查询退化为全表扫描。

新增原生用例覆盖新旧入口上限、原文和状态不变、关键人改绑、第二连接提交客户可见性撤销，以及真实 EXPLAIN 和第二连接对其他商机关键人行的锁定。尚未执行这些原生用例，不以静态审查代替真实结果。

第二轮审查修正已提交的并发夹具清理：站点按真实 Address 删除；逐一清理该商机的独立关联记录、字段历史及这些记录的 Version／通知，并在提交后以当前读取断言记录不残留。

真实页面验收发现，仅有旧竞争备注而没有结构化竞争对手时，复盘引用区误报“尚未记录竞争信息”。引用区现在同时显示原文备注和结构化明细，均作为纯文本手动引用，并附商机 ID 与读取时的版本；不会自动选择丢单分类或提交结论。重新读取、切换商机或身份时清除旧备注，丢弃迟到响应。新增旧备注、HTML 文本和身份切换回归。
