# PR06 Demo 设备不可用提醒

基于 PR03 活动事实和 PR05 预警合同。现有 requested_equipment 是平台，assigned_equipment／resource_window 是自由文本；本项不从它们推断具体设备及时间。新增内部 Demo Resource 目录，经理录入真实设备编号、名称、平台及负责维护的工程师或经理，不预填虚构设备，不复用客户 Installed Tool。

经理管理目录；资源维护人和经理记录不可用时间、原因、恢复。经理或当前 Evaluation 工程师维护该 Demo 的具体设备与安排起止时间，销售按原 Demo 范围只读。时间按上海时区填写，采用左闭右开区间 [start, end)，首尾相接不算冲突。仅具体设备身份相同且未来安排与有效不可用区间相交才预警；Requested／Scope Confirmed／Sample Received／Scheduled／Testing 之外的阶段、已取消请求不纳入未来安排。缺设备或时间显示资料不足，不能显示为可用。目录的“停止新安排”只禁止新分配，不等同设备故障；故障必须填写不可用区间。

Warnings 与 Review 显示当前未来安排的资源风险，计数按受影响 Demo 去重，明细保留每个相交区间；此项是当前状态，不伪装成历史周期的资源状态。Self Test 在无客户地域／市场筛选时保留；按销售、地域、市场和设备筛选遵守各自来源。资源目录显示具体设备平台，经营统计的设备口径继续使用关联商机。

设备恢复、Demo 改期或退出测试阶段后当前风险消失。首次观察到的冲突保存不可变快照及时间，用于历史查看；旧自由文本和系统未观察过的过去冲突不补造历史。不可用区间和 Demo 安排各有语义版本，只有设备／时间／有效状态改变才形成新实例；重复保存或只改说明不重复通知。通知复用现有 CRM Notification，接收人必须仍能读取原 Evaluation，记录指向当前业务来源。

所有保存检查 modified，写入原生 Version 或 Evaluation History。目录、不可用区间与安排的变更通过统一资源锁串行化；无外部邮件、完整预约排程或自动改期。真实设备和维护责任由经理通过目录明确填写，仍需业务验收。

重新测试会清除上一轮设备和安排时间，并写入 Resource Schedule 历史；新的测试轮必须重新安排。界面使用明确 UTC+8 显示时分，展开 Demo 面板时读取实时版本，检测到外部更新时保留脏输入并要求刷新。

候选验证：3 项纯区间测试、权限源注册、Python 语法、TypeScript 检查通过；148 项相关 UI／接口回归通过，另补的 Review 跳转及 Warnings 当前／未知分离测试通过。新增 5 项原生 Frappe 测试待完整门禁执行；尚未声称后端门禁通过。

首轮对抗审查修复：冲突历史和通知按当前锁读去重，保存返回当前冲突快照；重新展开读取可用性，脏输入保留并提示刷新。停止新安排的设备仍可调整已有安排时间，清除后不能重新分配。增加真实双连接 RR 快照回归和停用设备改期原生测试（待门禁）；9 项设备 UI、3 项纯规则及类型检查通过。参数校验失败可直接改正输入，数据库日期范围校验及 staging 清理清单同步补齐。
