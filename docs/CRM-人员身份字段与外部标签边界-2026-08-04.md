# CRM 人员身份字段与外部标签边界

日期：2026-08-04

## 内部身份字段

下列字段在 repository、API DTO 与未来 Frappe DocType 中存 Frappe User `name`（本项目为 ASCII email），不存显示名：`owner`、`salesOwner`、`engineerOwner`、`actionOwner`、内部 `actor`、`approvedBy`、`createdBy`、`preparedBy`、`uploadedBy`、通知 `recipientId`。

Mock 的 `administrator`、`sales-user`、`fae` 等值只是身份切换键，禁止进入业务记录。真实后端从 `frappe.session.user` 取得当前用户，并覆盖 Actor、Approver、CreatedBy、UploadedBy 等服务端拥有字段。

## 不属于内部 User Link 的值

- 客户联系人：使用 Contact DocType ID；例如客户联系人 `CON-003` 可显示为“演示员工14”，但不得解析为 `person077@crm.example.invalid`。
- 外部参与者：例如 `Customer QE`，作为外部 actor label；不得创建虚假 Frappe User。
- 组织责任主体：例如 `Product Engineering`、`R&D Software`、`Quality`，属于 team/organization label；若未来需要可分配用户，必须另建字段并迁移。
- 流程文案：例如 `待安排`、`待测试`、`样片追加中`，只用于状态展示，不是 Actor ID。

## 迁移失败策略

受控映射表之外的内部人员值一律失败关闭。不得按姓名模糊匹配，不得把未知值原样写入 Link→User，不得把客户联系人姓名当作内部员工。部署迁移须先验证 User/Employee 均存在且角色符合预期，再在单一事务内写入。
