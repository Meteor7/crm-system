### 2.3 Frappe 异常归一层骨架(greenfield,不影响 mock)

在 `src/api/frappe-adapter.ts` 新增(不替换现有 `BACKEND_NOT_CONNECTED` 占位):
```ts
import { CrmApiError, type CrmApiErrorCode } from './contracts'

/** Frappe 异常 / HTTP 状态 / 网络错误 → CrmApiError 的归一映射(骨架)。
 *  Stage 1 仅落骨架;真实映射在 Frappe adapter 实现时补全。 */
export function normalizeFrappeError(error: unknown, requestId: string): CrmApiError {
  // TODO(Frappe 接入):按上游契约第 4 节错误码枚举表实现 PermissionError→PERMISSION_DENIED/SCOPE_DENIED、
  // ValidationError→VALIDATION_ERROR、TimestampMismatch→VERSION_CONFLICT、401→UNAUTHENTICATED、
  // 5xx→INTERNAL_ERROR(retryable)、网络/超时→NETWORK_ERROR/UPSTREAM_TIMEOUT(retryable)。
  if (error instanceof CrmApiError) return error
  const message = error instanceof Error ? error.message : '数据请求失败,请稍后重试。'
  return new CrmApiError('INTERNAL_ERROR', message, requestId, true)
}
```
> 注意:`UNAUTHENTICATED` 出现在上游契约第 4 节的归一目标里,但**当前无人抛出/构造它**。为避免 union 出现"死成员"歧义,本轮**暂不**把 `UNAUTHENTICATED` 加入 union;等 Frappe 归一层真正产出它时再加。如 Codex 判断需要,可在 union 末尾加 `| 'UNAUTHENTICATED'` 并注明 reserved。

### 2.4 `request-state.ts` denied 数组

`src/api/request-state.ts:37` 的 `denied` 判定保持不变(它是 `string[]` 的 `.includes(error.code)`,`error.code` 为 union 时类型兼容)。**在上方加注释**说明其与 union 的关系:
```ts
// denied 家族:角色级权限(PERMISSION_DENIED)与数据范围越权(SCOPE_DENIED)。
// NOT_PERMITTED / '403' 为 Frappe HTTP 翻译预留,当前 Mock 不抛出;归一层应把它们映射到上述两者。
denied: ['PERMISSION_DENIED', 'SCOPE_DENIED', 'NOT_PERMITTED', '403'].includes(error.code),
```
