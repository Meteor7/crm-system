# Review stage conversion and pipeline coverage (#19 / #20 slice)

Review adds five historical ratios: S1→S2, S2→S3, S3→S4, S4→S5 and S5→S7. S6 is optional. Per the Sales Cockpit handoff §4.2, each ratio divides distinct opportunities that reached the destination stage by distinct opportunities that reached the source stage during the trailing 24 calendar months ending at the selected Shanghai cutoff. The start is midnight on the matching calendar date 24 months earlier (clamped for leap day), both dates inclusive. Repeated arrivals count once per opportunity per stage; detail rows show the latest arrival inside the window. Lost and won opportunities remain in the history.

These are independent stage-arrival counts, not today's funnel populations or a same-entry-cohort calculation. For example, two Demo arrivals and one qualified arrival in the window produce 200% if one qualification predates the window. The UI explains this; ratios are not capped at 100%. No skipped stage is inferred from a later/current stage.

Only exact `recorded`, `declared` and `evidence` arrival dates count. Missing/approximate dates and unverified history coverage make rates unavailable, while known samples remain inspectable. Configure `crm_cockpit_history_complete_from.stage` only after the source history has actually been verified to cover the entire window. Historical sales filtering also needs the existing field-history coverage marker. Sales ownership is replayed at the selected cutoff; region and market use current customer master values, matching Review. A zero source count is N/A; a verified nonzero source count with no destination arrivals is 0%. Ratios below 45% are highlighted. `crm_cockpit_conversion_threshold` accepts 0–100 (including decimals); invalid values fall back to 45.

Coverage is the sum of the same five S2–S6 CNY amount metrics displayed by Review, divided by **annual target − actual YTD CNY order intake**. It excludes S1 and won PO amounts from the numerator. It reuses the existing individual annual target and booking rules rather than introducing a second ledger or exchange-rate calculation. Missing amounts/history remain unavailable. An unset annual target stays unset; a met/exceeded target is N/A rather than an infinite/negative ratio. The 3–4× range is a reference, not a probability forecast.

Targets currently apply only to a single salesperson with no region/market filter. Coverage explains this restriction; no team target is fabricated or allocated. All detail drilldowns retain existing Manager-only access, validated scope and pagination. No schema change is needed.

Validation covers history deduplication, lost/won records, optional S6, date/time boundaries and leap day, owner replay, incomplete migration evidence, zero denominators, thresholds, target scope/missing/achieved states, real database history and targets, authorization, and frontend drilldowns. This slice does not close all of #19 or #20: territory/team targets and other unimplemented cockpit scope remain separate work.
