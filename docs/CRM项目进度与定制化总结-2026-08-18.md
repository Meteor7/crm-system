## 1. 项目结论

项目已经从早期界面 Demo 演进为一套具有真实前后端、正式数据持久化和业务权限控制的半导体行业 CRM。当前主业务链已经贯通：

```text
Lead
  -> Account / Contact
  -> Opportunity
  -> Demo Request
  -> Demo Test / Wafer 验证
  -> Quotation / Booking
  -> Installed Tool
  -> 服务、版本和受控文档记录
```

参照 Salesforce 的 CRM 能力框架，项目已经覆盖客户主数据、销售过程、商机管理、活动管理、报价、经营分析和设备资产等核心领域。在此基础上，项目没有停留在通用 CRM 字段层面，而是重点完成了半导体设备销售所需的 Demo 审批、晶圆测试、跨角色状态门禁、报价版本、设备交付生命周期和技术资料受控交付。

当前可以作出以下判断：

- 核心业务功能完成度较高，已具备从线索到设备档案的完整演示和业务操作主线。
- 行业定制完成度较高，Demo 与 Wafer Test、报价、Installed Tool 已形成明确的专用数据模型和流程规则。
- 前后端一体化已经落地，正式运行使用 Frappe API、DocType 和 MariaDB，不依赖生产 Mock 数据。
- 工程质量已具备持续交付基础，当前前端类型检查、102 个测试文件共 668 个用例以及 Frappe 模式生产构建均已通过。
- 正式上线前仍需完成真实部署环境的后端集成回归、人工 UAT、安全整改复核和运维验收。

## 4. 相对通用 CRM 的定制化价值

### 4.1 半导体售前验证不是附属备注，而是正式业务对象

项目将 Salesforce 中通常需要通过 Custom Object、Flow 和 Approval Process 组合配置的售前验证过程，直接建模为 Demo Request、Evaluation、Test Run 和 Demo Artifact。销售、工程和经理在同一条记录链上协作，审批通过后自动创建验证任务，避免依靠邮件、Excel 和口头交接。

### 4.2 商机阶段由真实业务证据驱动

商机阶段并非完全依赖销售手工选择。创建 Demo Request、Manager 审批并创建 Evaluation、Evaluation 最终 Accepted 等事件会自动推进商机。关键阶段不能通过普通编辑跳过；Manager 回退需要原因并进入历史。这种设计更适合设备型长周期销售，也提高了 Pipeline 数据可信度。

### 4.3 Wafer Test 指标进入 CRM 主链

Demo Test 不只记录“成功/失败”，还承载 Wafer 数量、Capture、False Positive、测试截止日期、执行记录、偏差和客户评审等验证信息。销售可以在商机上下文中看到工程进度，工程也能在客户和商机背景下完成测试记录。

### 4.4 报价采用公司业务模板和受控版本

报价模块使用自定义 Quotation 数据模型，而不是简单复用通用表单。系统支持设备、配件和服务的差异化编辑，统一计算金额和折扣，记录付款条款、版本、审批、发布和客户决定，并由服务端基于同一版本快照生成预览及正式 PDF，便于保持公司报价版式和数据一致性。

### 4.5 Booking 与设备交付档案连续衔接

Booking 可以转换为 Installed Tool，设备从销售结果进入以序列号为核心的一机一档。系统围绕 FAT、Shipment、Installation、SAT、Warranty、Completed 等阶段维护交付状态，并独立记录软件/固件版本和服务事件，使 CRM 能够继续覆盖设备交付后的客户运营。

### 4.6 技术文档采用受控交付机制

Document Center 不只是普通附件列表。文档支持分级、访问申请、Manager 决策、水印版或原件分发、上传审批、版本和下载审计，适合半导体设备资料、方案、测试报告和客户交付文件的受控使用场景。

### 4.7 客户结构适配 Fab / Site 场景

Account 下可维护多个 Site，联系人、商机、Booking 和 Installed Tool 可以保留具体厂区语义。客户领域支持在既有选项之外登记新的业务分类，适应公司后续拓展不同半导体工艺、应用或客户分层，而不需要为每次分类调整修改前端代码。

## 6. 技术与交付成熟度

### 6.1 系统架构

- 前端采用 Vue 3、TypeScript、Pinia、Vue Router、Element Plus 和 ECharts。
- 正式运行通过 `src/api/frappe-adapter.ts` 调用 `rayher_crm.api.v1`。
- 后端采用 Frappe/ERPNext 运行栈，自定义 DocType、服务层、权限层和 API；MariaDB 为正式数据存储。
- Mock adapter 只用于自动化测试注入，不作为开发或生产的数据运行模式。
- 前端可以构建到 Frappe App 的 `public/crm`，由 Frappe 会话和 CSRF 机制承接登录态。
- 本地 Compose 拆分前端、后端、MariaDB、Redis、Worker、Scheduler、WebSocket 和 ClamAV，并保留备份恢复演练脚本。

### 6.2 数据与权限可靠性

- 后端以 Manager、Sales、Engineer 三种 CRM 角色解析能力，歧义角色默认拒绝访问。
- 关键记录同时执行角色能力和行级范围校验，降低仅靠前端隐藏按钮造成的越权风险。
- 商机、Demo、报价、Installed Tool 等更新使用服务端状态机、事务和乐观并发控制，避免旧页面静默覆盖新数据。
- 文件采用私有存储、类型检查、病毒扫描和审计等机制；受控文档有独立的访问决策流程。
- 正式构建不包含 Mock 客户数据运行入口。

## 8. 推荐演示路径

建议使用以下路径展示当前项目的定制化完成度：

1. 从 Lead 创建并转换客户、联系人和商机。
2. 在 Opportunity 中查看阶段、概率、Forecast、关键人、风险和行动计划。
3. 创建关联商机的 Demo Request，依次展示 Sales、Engineer、Manager 的操作边界。
4. 审批后进入 Demo Test，记录 Wafer Test Run、截止日期、结果和客户评审。
5. 展示业务事件如何自动推进商机关键阶段，以及 Manager 带原因回退。
6. 为商机创建 Quotation，编辑设备/配件/服务与付款条款，演示版本、审批和 PDF。
7. 确认 Booking 并转换为 Installed Tool，展示一机一档、交付阶段、版本和服务历史。
8. 在 Document Center 演示受控文档的申请、审批、水印交付和审计。
9. 回到信息中心和 Account 360，查看同一客户的销售、验证、报价、设备和行动全景。

## 9. 总结

本项目已经具备成熟 CRM 的基础对象和销售管理框架，同时建立了鲜明的半导体行业定制能力。其核心价值不是“做一个缩小版 Salesforce”，而是把公司真实存在的销售、工程验证、报价、设备交付和技术资料协作整合为一条可执行、可追溯、可授权的业务链。

从当前完成度看，产品建设重点已经由“补齐核心模块”转向“真实环境验收、数据初始化、安全复核和上线运维”。在保持现有行业主线稳定的前提下，后续再逐步增强预测、活动协同、服务和分析能力，会比继续横向堆叠通用功能更有价值。
